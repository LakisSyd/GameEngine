# Единая книга DX Framework

Издание 10.0 объединяет учебник, справочник, атлас исходников и практикум. Оно написано по снимку репозитория от 1 ноября 2026 года. Главный принцип книги: сначала понять данные и правило, затем пройти путь одного кадра по реальному коду, после этого сделать маленькое изменение и доказать результат отладкой.

## Что входит в книгу

| Часть | Что изучаем | Практический результат |
|---|---|---|
| Основа | C++ ECS время векторы матрицы лучи | читаешь выражение и можешь вручную предсказать результат |
| Ядро | кадр приложение ввод сцена ресурсы | понимаешь где начинается и заканчивается ответственность системы |
| Рендер | DirectX 11 камеры материалы шейдеры | прослеживаешь данные от Transform до пикселя |
| Bullet | мир тела формы фильтры запросы контроллеры constraints | умеешь создать проверить и отладить физический объект |
| Игровые системы | энергия атмосфера двери ремонт инвентарь эффекты | добавляешь механику полным вертикальным срезом |
| NPC | восприятие память решение навигация укрытие оружие урон | расширяешь AI отдельными модулями без монолитного Update |
| Инженерная практика | владение тесты профилирование сохранения диагностика | сохраняешь проект управляемым по мере роста |
| Учебный маршрут | задания от одного вечера до четырёх недель | учишься через собственные изменения а не через копирование |

## Что означает построчный разбор

Построчный разбор не является перепечаткой каждого include и каждой закрывающей скобки. Для каждой подсистемы книга выделяет её рабочий путь: вход, проверки, чтение компонентов, вычисление, запись результата и побочные эффекты. Каждая значимая строка объясняется по четырём вопросам.

1. Что строка читает.
2. Что строка изменяет.
3. Почему она стоит именно здесь.
4. Как проявится поломка её контракта.

Одинаковый служебный шаблон, например guard clause или `ForEach`, подробно объясняется один раз. В следующих системах книга указывает, какую роль этот шаблон играет в новом контексте. Так сохраняется построчность причин, но не создаётся сотня страниц одинаковых объяснений скобок.

## Карта текущего проекта

| Каталог или файл | Ответственность | Главный вопрос при чтении |
|---|---|---|
| `src/Core` | запуск кадр время фоновые задания физический мир | кто вызывает систему и на каком времени |

| `src/Scene` | создание удаление загрузка сохранение освещение | что является authoring данными а что runtime состоянием |
| `src/Assets` | асинхронная подготовка и загрузка ресурсов | на каком потоке разрешена операция |
| `src/Input` | сырые клавиши мышь фронты нажатий | требуется состояние или событие одного кадра |
| `src/Render` | DirectX ресурсы кандидаты материалы шейдеры | в каком пространстве и формате находятся данные |
| `src/Animation` | клипы поза контроллер IK оружия | кто выбирает действие и кто только строит позу |
| `src/Physics` | общие запросы к Bullet | какой объект игнорируется и какой фильтр используется |
| `src/Gameplay/Player` | ввод намерение движение камера параметры | где заканчивается желание игрока и начинается исполнение |
| `src/Gameplay/Interaction` | зоны события взаимодействия | какое событие одноразовое и кто его потребляет |
| `src/Gameplay/Inventory` | предметы слоты экипировка | какая Entity владеет предметом сейчас |
| `src/Gameplay/Combat` | оружие выстрел урон ближний бой | где подтверждён факт попадания и когда применяется урон |
| `src/Gameplay/AI` | задачи навигация дистанция сквадовые заготовки | это факт решение или исполнение |
| `src/Gameplay/Power` | генерация распределение потребление | единицы мощности и правило приоритета |
| `src/Gameplay/Ship` | комнаты среда тревога подлодка culling | какая величина переносится между отсеками |
| `src/Gameplay/Repair` | повреждение меша и ремонт | какая операция синхронная а какая фоновая |
| `src/Gameplay/Effects` | частицы взрывы импульсы | является эффект причиной или визуальным следствием |

| корневые `Npc*.h` и `StateSystem.h` | текущий модульный AI | кто наблюдает кто решает кто исполняет |

## Главная схема одного кадра

```text
Windows input
    -> InputManager и GameInputFrame
    -> игровые намерения игрока и NPC
    -> решения AI и команды
    -> движение оружие взаимодействия среда
    -> Bullet fixed steps
    -> синхронизация Transform
    -> анимация и IK
    -> сбор render candidates
    -> DirectX 11 draw calls
    -> ImGui и отладочные представления
```

Стрелка означает передачу факта или намерения. Она не означает, что следующий слой должен заново принимать решение предыдущего слоя. Например, `NpcRangedCombatSystem` решает, разрешена ли попытка огня, а `WeaponSystem` не выбирает тактику: он проверяет механическую готовность оружия, строит фактический луч и создаёт событие урона.

## Три вида данных

| Вид | Примеры | Правило |
|---|---|---|
| Authoring | размер коллайдера урон оружия приоритет питания | сохраняется в сцене и редактируется человеком |
| Runtime | таймер перезарядки текущая скорость путь NPC | создаётся или изменяется во время симуляции |
| Derived | мировая матрица powerRatio видимость цели | вычисляется из других данных и не должна иметь двух независимых владельцев |

Большинство трудноуловимых багов возникает, когда производное значение начинают редактировать как исходное или когда два слоя считают себя владельцами одного Transform.

## Как заниматься по книге

Для каждой темы используй цикл из пяти шагов.

1. Запиши ожидаемое поведение простыми словами.
2. Нарисуй данные до и после системы.
3. Рассчитай один пример вручную.
4. Найди первую строку реального кода, которая может изменить результат.
5. Проверь в движке видимым индикатором, трассером, журналом или тестовой сценой.

Если после запуска результат неожиданен, не меняй сразу несколько коэффициентов. Сначала найди первый переход, где фактическое значение расходится с записанным ожиданием.

## Обозначения

| Обозначение | Значение |
|---|---|
| Инвариант | условие которое обязано оставаться истинным |
| Guard clause | ранний выход при недопустимом входе |
| Владелец | код который отвечает за создание изменение и уничтожение ресурса |
| Источник истины | единственное место откуда берётся окончательное значение |
| Intent | желание выполнить действие ещё не гарантированное физикой |
| Fact | уже подтверждённое событие например попадание луча |
| Fixed step | шаг симуляции постоянной длительности |
| Query | чтение мира без изменения его состояния |
| Command | запрос изменить состояние позже или в определённом слое |

## Учебное обещание издания

После полного прохождения книги ты должен уметь открыть незнакомую систему проекта и ответить на семь вопросов: кто её вызывает, какие компоненты она читает, какие компоненты пишет, на каком времени работает, какие ресурсы не владеет, что обязано быть истинно на входе и каким наблюдаемым признаком доказать её работу.
