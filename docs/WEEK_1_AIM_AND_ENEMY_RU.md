# Неделя практики: прицеливание и враг с винтовкой

Это самостоятельный учебный маршрут для **текущего** DX_FrameWork: семь основных этапов и отдельные дополнительные миссии. Ориентир — 25–35 часов на неделю, если сделать четыре обязательные дополнительные миссии; остальные оставлены на выбор. Код за тебя здесь не написан: фрагменты показывают принцип и место интеграции. После каждого дня запускай Play и проверяй результат; не копи семь дней непроверенных изменений.

**Две главные задачи:** (1) зажатая ПКМ поднимает винтовку в удобную стойку, а нажатие колёсика при удерживаемой ПКМ переключает точное прицеливание; (2) в сцене есть враждебный NPC, который замечает игрока, стреляет по нему, промахивается при преграде и может быть побеждён. Дополнительные миссии развивают отдачу, реакцию на попадание, патруль, боеприпасы, смену оружия и интерактивность.

**Текущий жанр:** стрелковая игра с персонажем, винтовкой и врагами. Системы затопления, подлодки, ремонта пробоин, атмосферы и энергетики относятся к старому формату проекта. В заданиях этой недели они не участвуют.

**Тестовая площадка** ниже — отдельная маленькая сцена для быстрой проверки камеры, оружия и NPC. Это инструмент разработчика, а не игровой режим и не требование делать волны врагов.

## Теория, которая пригодится всю неделю

### Ввод и состояния

`Down` означает «кнопка удерживается сейчас», `Pressed` — переход из отпущенного состояния в нажатое только в этом кадре, `Released` — обратный переход. Для стойки на ПКМ нужен `Down`; для переключателя по колёсику — `Pressed`. `PrecisionAim` должен действовать только при `Aim`:

```cpp
// Схема в игровой системе, не готовая вставка в конкретный класс.
const bool shoulderAim = input.Down(GameAction::Aim);
if (!shoulderAim) precisionAim = false;
else if (input.Pressed(GameAction::PrecisionAim)) precisionAim = !precisionAim;
```

Учитывай блокировку игрового ввода, когда F2 отдаёт мышь интерфейсу. Не опрашивай Windows-мышь ещё раз прямо в камере: `GameplayInputSystem::Sample` уже формирует один согласованный снимок ввода на кадр.

### Время и плавность

Переход камеры или оружия хранит текущее значение и приближается к цели с учётом `dt` (секунды кадра). Простое `value += (target - value) * 0.15f` даёт разную скорость на 30 и 144 FPS. Для сглаживания с постоянным временем:

```cpp
float alpha = 1.0f - std::exp(-speedPerSecond * dt);
value += (target - value) * alpha;
```

При `speedPerSecond = 10` переход быстрый, при `5` — мягче. Для позиции интерполируй каждый компонент или `XMVECTOR`. Для углов рядом с переходом через ±180° считай кратчайшую разницу, а не обычную разницу чисел. `dt` ограничь разумным максимумом после паузы/отладки, иначе камера может прыгнуть.

### Координаты и выстрел

`TransformComponent` хранит мировое положение персонажа; точка дула в `WeaponComponent::muzzlePosition` задана в **локальных координатах модели оружия**. Чтобы получить мировую точку, применяют `XMVector3TransformCoord(localMuzzle, rifleWorld)`. Направление преобразуют `XMVector3TransformNormal(localForward, rifleWorld)` и нормализуют. Точка и направление — разные операции: перенос нельзя применять к направлению.

Для точного выстрела из третьего лица удобно сначала получить точку под прицелом лучом из камеры, затем направить пулю **от дула** к этой точке. Второй луч от дула проверяет, не закрывает ли винтовку стена; если закрывает, пуля должна попасть в стену. Для первого лица в `ApplicationClass.cpp` уже рассчитывается `firstPersonAim` по дулу после обновления модели. Не смешивай экранный центр, локальную координату оружия и мировой вектор.

### Источник истины

У `NPCComponent` есть `health`, у `DamageableComponent` тоже. Текущий `DamageSystem` обрабатывает `PlayerComponent` и `DamageableComponent`; сам по себе `NPCComponent::health` не уменьшает. Для учебного врага выбери один источник истины (проще `DamageableComponent`) и отображай/синхронизируй его в UI. Два независимо изменяемых здоровья приведут к «мертвому, но стреляющему» врагу.

## День 1. Модель прицеливания и состояния

**Результат:** игра понимает три состояния: `Hip` (обычное), `Shoulder` (ПКМ), `Precision` (ПКМ + переключатель СКМ). Пока без сложной анимации.

1. Найди место получения `gameInput` в `ApplicationClass.cpp` и зафиксируй, где `m_cameraController.UpdateFollowLook` и `UpdateFollow` используют камеру. Проследи путь `Aim` от привязки до кадра.
2. Добавь небольшое игровое состояние прицела рядом с кодом игрока, например `enum class AimMode { Hip, Shoulder, Precision };`. Это **текущее** состояние, а не настройка сохранённого профиля оружия.
3. При `Aim.Down() == false` возвращай `Hip`. При удержании — `Shoulder`; при `PrecisionAim.Pressed()` переключай `Precision`/`Shoulder`. При отпускании ПКМ сбрасывай точный режим; повторное нажатие ПКМ начинает со стойки на плече.
4. Сделай простую диагностику: текущий режим в debug HUD или `OutputDebugStringA` только **при смене состояния**, чтобы журнал не печатал строку 60 раз в секунду.
5. Проверь таблицу переходов:

| Действие | Было | Стало |
|---|---|---|
| Зажать ПКМ | Hip | Shoulder |
| Нажать СКМ при ПКМ | Shoulder | Precision |
| Нажать СКМ ещё раз | Precision | Shoulder |
| Отпустить ПКМ | любое прицеливание | Hip |
| Нажать СКМ без ПКМ | Hip | Hip |

**Типичная ошибка:** `Pressed(Aim)` держит режим всего один кадр. **Критерий:** режим сохраняется при удерживании и не меняется, когда мышь занята UI.

## День 2. Камера и оружие для стойки на плече

**Результат:** камера и винтовка плавно переходят в плечевой режим и возвращаются назад без рывка.

1. Запиши исходные параметры камеры из текущего `PlayCameraComponent`/`CameraController`: дистанцию и `thirdPersonTargetOffset`. Не зашивай текущую позицию камеры как «начальную» каждый кадр: исходная игровая настройка должна сохраняться отдельно.
2. Создай два набора **целевых** смещений: `Hip` и `Shoulder`. Начни с малого изменения плечевого смещения и дистанции. Проверяй при игроке у стены, при наклоне вверх/вниз, в движении и на месте.
3. Храни `currentDistance`/`currentOffset` и приближай к целям формулой сглаживания выше, перед `UpdateFollow`. Если `ApplicationClass.cpp` каждый кадр вновь вызывает `SetThirdPersonDistance` из `PlayCameraComponent`, найди одну точку, где сначала выбирается базовое значение, потом применяется временная поправка прицела. Иначе сглаживание будет перезаписываться.
4. Посмотри `src/Animation/AnimationController.h`: при экипированной винтовке там уже выбирается `weapon->rifleIdleAnimation` для верхнего слоя, а выстрел временно включает `rifleGunAnimation`. Поэтому для первого результата можешь **оставить существующую позу рук** и менять только камеру/временное смещение винтовки. Если нужна отдельная поза ПКМ, добавь её как отдельный animation state/clip и плавный переход; не подменяй название `rifleIdleAnimation` каждый кадр. Винтовка прикрепляется через `BoneAttachmentComponent`; если включён IK левой руки, поправку к оружию применяй до вычисления IK, иначе ладонь отстанет.
5. Для `Precision` сначала переведи в уже существующий вид от первого лица и верни прежний вид при отпускании ПКМ. Если позже захочешь именно уменьшать FOV, его базовая матрица создаётся в `src/Render/D3DClass.cpp`, а `ApplicationClass.cpp` берёт её через `GetProjectionMatrix`. Понадобится управляемое пересоздание матрицы проекции до расчёта крестика и рендера; не меняй лишь визуальный масштаб модели оружия.

**Мини-пример:** при `dt=0.016`, `speedPerSecond=8`, `alpha≈0.120`, то есть значение за один кадр проходит около 12% оставшегося расстояния. Через секунду оно почти у цели независимо от FPS.

**Критерий:** переход похож при 30/60/144 FPS; после переключения вида через `GameAction::ToggleView` (сейчас клавиша `V`) нет резкой смены дистанции. `F2` освобождает мышь для игрового UI — в этом режиме прицел не должен реагировать на щелчки по интерфейсу. Проверь также отпускание ПКМ во время перезарядки и смены оружия.

## День 3. Пуля идёт туда, куда показывает прицел

**Результат:** в обоих видах урон и нарисованный прицел совпадают с попаданием; ближняя стена перехватывает пулю.

1. Прочитай `WeaponSystem::Update`. Сейчас система рассчитана на игрока: сама ищет `PlayerGameTag`, берёт его оружие, читает `GameAction::Fire` и создаёт `DamageEvent`. Эту функцию не надо вызывать для бота с подменённым вводом.
2. Пройди существующий путь первого лица в `ApplicationClass.cpp`: после `m_sceneManager.UpdateAll` формируется `firstPersonAim`, затем вызывается `WeaponSystem::Update`. Подумай, когда меняется модель прицела, чтобы не использовать положение дула из предыдущего кадра.
3. Для плечевого вида сначала возьми точку цели из луча камеры. Если он ничего не встретил, цель = камера + направление × дальность. Затем вычисли `direction = normalize(target - muzzleWorld)` и выполни второй `PhysicsRaycast::CastRay` от дула. Игнорируй объект стрелка через параметры `ignoredEntity`/`ignoredObject`.
4. На время отладки рисуй два луча разными цветами или печатай мировую точку пересечения. Если центр крестика на враге, а урон уходит в сторону, проверь матрицы, `muzzlePosition`, ось `+Z` винтовки и положение камеры.
5. Удостоверься, что `damageEvent.target` равен сущности персонажа с `PlayerComponent`/`DamageableComponent`, а не отдельной сущности визуальной модели. Если Bullet сообщает дочерний collider, нужен явный owner mapping.

```cpp
// Упрощённая геометрия: targetWorld получен камерой, muzzleWorld — моделью.
XMVECTOR delta = XMVectorSubtract(XMLoadFloat3(&targetWorld),
                                  XMLoadFloat3(&muzzleWorld));
if (XMVectorGetX(XMVector3LengthSq(delta)) > 1e-6f) {
    XMFLOAT3 direction{};
    XMStoreFloat3(&direction, XMVector3Normalize(delta));
    // PhysicsRaycast::CastRay(muzzleWorld, direction, world, range,
    //                         shooterEntity, shooterBody, hit);
}
```

**Критерий:** две цели на разной дистанции, стена перед дулом, цель у края экрана и стрельба от бедра/с плеча/в точном режиме дают понятный результат.

## День 4. Первый враждебный NPC: состояние и обнаружение

**Результат:** один неподвижный враг видит игрока в пределах дистанции и не видит сквозь стену.

1. Добавь в тестовую сцену NPC с `NPCComponent::isHostile = true`, физическим `CharacterController`/коллайдером, `TransformComponent`, `ActiveComponent` и одним выбранным компонентом здоровья. `DamageSystem` пропускает цель без `ActiveComponent`. Пока оставь врага неподвижным: навигация добавит слишком много новых причин ошибки.
2. Создай отдельные данные боя врага, например дистанцию обнаружения, угол обзора, время между выстрелами, `lastSeenPosition`, состояние `Idle/Alert/Attack`. Не складывай их в `WeaponComponent`: оружие описывает оружие, AI — принятие решения.
3. Расстояние вычисляй из мировых позиций. Для конуса зрения нормализуй горизонтальные векторы и сравни скалярное произведение с `cos(halfFovRadians)`. Пример: угол обзора 120° ⇒ половина 60° ⇒ порог 0.5. Близкая цель за спиной должна быть видна только если ты явно хочешь круговой обзор.
4. Проверь прямую видимость `PhysicsRaycast::CastRay` от точки глаз NPC к груди игрока. Игнорируй collider самого NPC. **Только первое попадание по игроку** означает видимость; первое попадание по стене означает препятствие. Нулевая/невалидная длина вектора не должна попадать в нормализацию.
5. Покажи диагностически состояние и причину (`out of range`, `outside FOV`, `wall`, `visible`). Обновляй решение в игровом ходе до перемещения NPC; сравни порядок с `NpcUtilitySystem` → `StateSystem` → `CharacterControllerSystem` в `ApplicationClass.cpp`.

```cpp
// Это математический смысл проверки FOV; вычисление forward зависит от рига.
float dot = XMVectorGetX(XMVector3Dot(forwardXZ, toPlayerXZ));
bool inCone = dot >= std::cos(XMConvertToRadians(60.0f));
bool canSee = inRange && inCone && firstRayHit.entity == playerEntity;
```

**Критерий:** враг замечает игрока спереди, теряет его за стеной и не атакует при паузе/в редакторе.

## День 5. Враг стреляет и получает урон

**Результат:** NPC стреляет с ограниченным темпом; пули блокируются стеной; игрок теряет здоровье; убитый враг прекращает атаку.

1. В боевой системе NPC храни кулдаун на **каждом NPC/оружии**, уменьшай на `dt`, стреляй при `cooldown <= 0`, видимой цели и ненулевом здоровье. Ставь `cooldown = 1 / fireRate` даже если промахнулся — тот же принцип уже есть в `WeaponSystem`.
2. Дай NPC своё оружие. Простой учебный вариант — `WeaponComponent` на сущности NPC: `WeaponSystem::GetEquippedWeaponEntity(registry, npc)` умеет возвращать такой legacy fallback. Более чистый вариант — отдельная сущность оружия с `WeaponComponent`/`WeaponOwnerComponent` и `EquippedWeaponComponent` на NPC. В обоих случаях проверь `fireRate > 0`, дальность и урон. Видимую модель винтовки прикрепи к костям/сокету отдельно от боевой логики.
3. Формируй луч от дула/точки огня NPC к груди игрока и вызывай `PhysicsRaycast::CastRay`. Не стреляй напрямую в `player.health`: это обойдёт стены, очередь событий и единый путь урона.
4. При попадании создавай `DamageEvent` с `source = enemyWeaponEntity` или NPC, `target = hit.entity`, количеством урона, позицией/нормалью попадания и `Physical`; добавляй его через `DamageSystem::AddDamageEvent`.
5. Поставь вызов обновления врага с учётом текущего порядка: сейчас `m_damageSystem.Update` выполняется **раньше** `WeaponSystem::Update`, поэтому событие выстрела, добавленное позже, применяется в следующем кадре. Это допустимая задержка в один кадр. Реши и задокументируй, нужен ли один общий этап применения урона после обоих стрелков; не вызывай `DamageSystem::Update` дважды случайно.
6. Для смерти врага проверяй фактический компонент здоровья после обработки событий. Отключи его атаку, движение и при необходимости физический collider. При смерти игрока прекрати управление/стрельбу и покажи понятный HUD.

```cpp
if (visible && cooldown <= 0.0f && enemyAlive) {
    cooldown = 1.0f / fireRate;  // fireRate > 0 проверен раньше
    PhysicsRaycastHit hit{};
    if (PhysicsRaycast::CastRay(origin, direction, world, range,
                                enemyEntity, enemyBody, hit)) {
        DamageEvent event{};
        event.source = enemyEntity;
        event.target = hit.entity;
        event.damageAmount = damage;
        event.damageType = DamageEvent::DamageType::Physical;
        event.hit_position = hit.position;
        event.hit_normal = hit.normal;
        damageSystem.AddDamageEvent(event);
    }
}
```

**Критерий:** 5 секунд видимого игрока при `fireRate=2` дают около 10 попыток выстрела, а не по одной на кадр; стена сохраняет здоровье игрока; попадание игрока в NPC уменьшает то же здоровье, по которому определяется смерть.

## День 6. Движение, укрытие и боевой цикл

**Результат:** враг подходит на дистанцию атаки, останавливается, стреляет, теряет игрока за препятствием и возвращается к поиску/ожиданию.

1. Добавь простые состояния `Idle → Chase → Attack → Search → Idle`; ограничься одним врагом. Не меняй `NpcBrainComponent::command` каждый кадр без необходимости: его `revision` и построение маршрута будут постоянно сбрасываться.
2. На переходе `Idle → Chase` назначь цель игрока командой `FollowEntity`, если готовый `StateSystem` подходит твоему уровню, либо отдельным управлением `CharacterMovement`. У системы должен быть один владелец движения NPC в этом кадре. `NpcUtilitySystem` уже пропускает `isHostile`; проверь это в коде перед тестом.
3. В `Attack` останавливай движение на удобной дистанции, разворачивай модель/ствол к игроку и проверяй LOS перед **каждым** выстрелом. При потере LOS храни последнюю увиденную позицию и иди туда ограниченное время; не используй точное текущее положение невидимого игрока.

### М1. Отдача, разброс и замедление в прицеле

**Зачем.** Оружие должно ощущаться по-разному при стрельбе от бедра, с плеча и через прицел. Раздели три эффекта: (а) визуальная отдача двигает камеру/оружие, (б) разброс меняет направление выстрела, (в) прицеливание меняет скорость персонажа. Это разные переменные: красивый рывок камеры не должен тайно менять попадание.

**Теория и пример.** При каждом новом `shotsFired` добавь короткий импульс к угловой скорости камеры; между выстрелами возвращай отклонение к нулю. Для простого пружинного возврата:

```cpp
// angle и velocity — временное отклонение, не исходный yaw/pitch игрока.
velocity += (-stiffness * angle - damping * velocity) * dt;
angle += velocity * dt;
// Только при НОВОМ выстреле: velocity += recoilImpulse;
```

Разброс измеряй углом в радианах. Например, `Hip=2°`, `Shoulder=0.8°`, `Precision=0.15°`; тестовые числа подбирай на стенде. Изменяй направление луча **до** raycast, а крестик показывай по тому же правилу точности. Замедление: `effectiveSpeed = baseSpeed * aimMultiplier`, где `aimMultiplier`, например, `0.75` для плеча. Не умножай уже уменьшенную скорость снова каждый кадр — бери `baseSpeed` как неизменяемую основу.

**Шаги.** (1) Посчитай в `WeaponSystem` ровно один новый выстрел через изменение `shotsFired`. (2) Добавь визуальный импульс и возврат по `dt`; при паузе обновление не должно идти. (3) Добавь отдельную настройку разброса для трёх режимов, используй нормализованный мировой вектор. (4) Проверь одиночный и непрерывный огонь на стене с отметками попаданий. (5) В `GameplayController`/системе движения примени множитель скорости во время ПКМ; при отпускании скорость возвращается к исходной.

**Готово, когда:** удерживание огня даёт заметную, но контролируемую отдачу; точное прицеливание кучнее; скорость возвращается после ПКМ; при 30/144 FPS ощущение близкое. Если разброс усложняет отладку попаданий дня 3, временно ставь его в 0.

### М2. Попадание, здоровье и завершение боя

**Зачем.** Число HP без обратной связи выглядит как неисправный выстрел. Используй существующий путь `raycast → DamageEvent → DamageSystem`, а визуальный отклик строй по **подтверждённому** событию урона, чтобы маркер попадания не показывался на промахе.

**Теория и пример.** Сигнал попадания можно хранить как `hitMarkerRemaining = 0.12f` секунды; каждый игровой кадр `hitMarkerRemaining = max(0, hitMarkerRemaining-dt)`. Смерть срабатывает один раз на переходе `healthBefore > 0 && healthAfter <= 0`, а не каждый кадр после нуля. Отдельные состояния: `Alive`, `Dead` и, если нужно твоей игре, `Respawning`.

**Шаги.** (1) Проверь `DamageSystem.cpp`: `PlayerComponent` и `DamageableComponent` обрабатываются разными ветками, цель должна иметь `ActiveComponent`. (2) Выведи HP игрока и врага в HUD, причём NPC HP читай из выбранного источника истины. (3) Добавь краткий маркер попадания, эффект на экране при получении урона и понятный «победа/поражение». (4) При смерти врага останови решение AI и выстрел; при смерти игрока отключи управление и стрельбу. (5) Проверь попадание по стене, промах, добивающий выстрел, двойной `DamageEvent` в одном кадре.

**Готово, когда:** промах не даёт маркер, урон читается сразу, событие смерти исполняется один раз, «мёртвый» NPC не стреляет.

### М3. Патруль, тревога и поиск последнего места игрока

**Зачем.** Враг, который только ждёт и стреляет, быстро становится предсказуемым. Добавь понятный маршрут между 2–3 точками, краткую фазу тревоги и поиск **последней увиденной позиции**, не текущей позиции невидимого игрока.

**Теория и пример.** Память — это данные `lastSeenWorldPosition` и `timeSinceSeen`. При видимости обнови их; при потере видимости увеличивай таймер: `timeSinceSeen += dt`. Переход `Attack → Search` происходит после короткой задержки, `Search → Patrol` — когда NPC дошёл до последней точки или истёк таймер. При новом обнаружении из любого состояния — `Alert/Attack`. Для устойчивости используй разные дистанции входа/выхода (гистерезис из дня 6).

**Шаги.** (1) На простой тестовой сцене расставь две точки и убедись, что NPC идёт между ними без игрока. Точки храни как данные, а не как случайные константы в системе. (2) Добавь `Alert` на 0.3–0.7 секунды перед первым выстрелом. (3) После потери LOS иди к `lastSeenWorldPosition`, затем вернись в патруль. (4) Показывай текущие state, target point и таймер в debug UI. (5) Проверь игрока за спиной, выход из-за стены, исчезновение за дальним укрытием и повторное появление.

**Готово, когда:** NPC не знает скрытую позицию игрока, не мгновенно стреляет при первом пикселе видимости и не застревает навсегда в `Search`. В старом `StateSystem` есть `Wander` и `FollowEntity`, но для патруля нужной тебе локации можешь написать простую систему движения без комнат корабля.

## Если что-то пошло не так

- **Прицел виден, но камера не меняется:** `ApplicationClass.cpp` каждый кадр выставляет базовые параметры из `PlayCameraComponent` — временная поправка применяется не в том месте.
- **Прицел совпадает только в одном виде:** смешаны луч камеры и луч дула; рисуй обе линии и выведи мировую точку попадания.
- **NPC видит сквозь стены:** проверяется дистанция/угол, но не первое попадание `PhysicsRaycast`; либо у стены нет активного Bullet collider.
- **NPC не теряет здоровье:** луч попал в визуальный дочерний entity, нет `ActiveComponent` либо у NPC нет компонента, который обрабатывает `DamageSystem`.
- **NPC чинит корпус вместо атаки:** дружественная Utility AI всё ещё управляет `isHostile`.
- **Два выстрела вместо одного:** один и тот же Fire обрабатывается двумя системами или кулдаун сбрасывается при каждой смене состояния.
- **Рывок после паузы:** сглаживание получает слишком большой `dt`; ограничь входной шаг, не домножай позицию на FPS.

## Шпаргалка по подключению в проект

**Короткий словарь:** `ECS` — сущность как ID, данные в компонентах, правила в системах; `LOS` (*line of sight*) — незакрытая лучом линия до цели; `FOV` — угол обзора (не путать с углом обзора камеры при зуме); `cooldown` — оставшееся время до следующего выстрела в секундах; `world/local` — координаты относительно всей сцены/родителя; `rig` — кости и ограничения анимации. Когда число выглядит неверно, сначала проверь его единицы и систему координат.

### Как сделать первого NPC без поиска по всему репозиторию

В редакторе меню создания содержит `Crew NPC (logic)` (`src/Editor/EditorUI.cpp`, `CreateEditorTemplate`). Оно добавляет `NPCComponent`, `NpcBrainComponent`, `NPCMovementComponent`, `CharacterMovement`, `CharacterController`, настройки физики, анимацию и компонент экипажа. В инспекторе есть раздел `NPC AI` и флажок `Hostile`. Этот шаблон — **логическая** сущность: проверь, что к нему привязаны видимая модель, Bullet collider и `ActiveComponent`. Через меню `Add Component` добавь `Damageable Component`; при обычном маршруте урона именно его HP уменьшается. Инспектор `NPC AI` показывает отдельное `NPCComponent::health`, которое пока не синхронизировано с `DamageableComponent::health`: не оценивай смерть по неверному полю. На первом тесте можно вывести оба числа рядом и сразу заметить расхождение.

Если collider создан у дочерней модели с другой Entity, `PhysicsRaycastHit::entity` будет ссылаться на дочерний объект. Сначала выведи ID попадания и ID NPC; если они различаются, добавь явное сопоставление «часть модели → владелец NPC» при обработке выстрела. Не угадывай владельца по имени модели.

### Как подключить новую систему

Для начала достаточно отдельного `EnemyCombatSystem.h` с данными/методом `Update`; вызови его **один раз** из игровой ветки `ApplicationClass.cpp`, рядом с NPC AI и `WeaponSystem`. Позже можно выделить `.cpp`. Если добавляешь `.cpp`, проверь `DX_FrameWork.vcxproj` и `.filters`: в этом проекте исходники перечислены явно, новый файл может не попасть в сборку автоматически. Сначала компилируй после создания пустого класса, затем добавляй LOS, затем выстрел. Это сокращает число возможных причин ошибки.

Пример интерфейса (спроектируй точные зависимости под свой код):

```cpp
// Входы перечислены явно: система не должна тайно читать мышь или искать глобалы.
EnemyCombatSystem::Update(registry, damageSystem,
                          PhysicsWorld::Get().GetWorld(),
                          playerEntity, simulationDeltaTime);
```

`NpcUtilitySystem` уже исключает `isHostile` из старых задач экипажа; для боевого `Chase` всё равно проверь, кто последним записывает `CharacterMovement` и состояние NPC. Для неподвижного врага день 4–5 не требует `StateSystem` менять движение.

### Как искать одну неисправность

Выводи цепочку значений в таком порядке: `GameInputFrame` → режим прицела/состояние AI → мировая позиция дула/глаз → направление луча → первая Entity попадания → `DamageEvent.target` → `DamageSystem` → HP. Если обрывается один шаг, следующий пока не исправляй. В лог выводи события или раз в полсекунды, чтобы 60 строк в секунду не спрятали проблему.
